# 11. The API may apply a swap the user has decided on

**Status:** Accepted · **Decided:** 2026-08-11 · **Recorded:** 2026-08-11

Amends the boundary drawn in [ADR 8](0008-the-gate-blocks.md) and the read-only
assumption in [ADR 4](0004-two-embedded-databases.md). Neither is reversed; both
are narrowed. ADRs are immutable, so this is the record of what changed rather
than an edit to those.

## Context

The gate blocks on a banned card and [the shortlist](0008-the-gate-blocks.md)
now names legal cards that resemble it. Acting on that still meant hand-editing
YAML, which is friction in the terminal and impossible in the browser — and the
browser is where this is heading.

ADR 8 rejected **auto-substitution**: a tool that quietly swaps cards is one
whose output you can no longer trust to be your deck. That reasoning is about
the tool making the *choice*. It says nothing about the tool carrying out a
choice the user has already made, which is a different act with a different
risk.

## Options considered

**Keep it read-only; print the command to run.** Safe, and it was the initial
recommendation. Rejected: it makes the terminal the only place a deck can
change, which is exactly the coupling to the CLI this project is trying to shed
before it is hosted.

**Let the tool pick and apply.** Rejected, unchanged from ADR 8. The judgement
is the deckbuilding, and handing it over is the thing that makes the output no
longer yours.

**Apply a swap the user specifies.** Chosen.

## Decision

One narrow write endpoint, `POST /api/decks/{slug}/swap`, and a CLI command
over the same implementation. It takes a card out, a card in, and a rationale.
It cannot add, delete, reorder or rename anything else.

Four conditions, all checked before anything is written:

1. **The caller names the incoming card.** Nothing is inferred, and the
   shortlist is a list to pick from, not a default.
2. **The caller writes the `why`.** Empty is refused, at the endpoint and again
   in the editor. Rule 4 says a card that cannot justify its slot is a card to
   cut, and a rationale generated by the tool is precisely the empty
   justification that rule exists to prevent. This is the condition that keeps
   ADR 8 intact: a machine may not author the reasoning.
3. **The card must be legal here** — in the corpus, legal in Commander, inside
   the commander's colour identity, and not already in the list.
4. **The source must be writable.** `DeckSource.writable` is checked in one
   place. It is always true today with a single local user; ADR 4's hosted
   model keeps the curated decks read-only for everyone but the maintainer, and
   this is where that will be enforced.

**The edit is surgical.** `decks/edit.py` rewrites only the lines belonging to
the one card entry and verifies, by parsing before and after, that nothing else
moved. This is not fastidiousness: deck history *is* git history (ADR 1) and
`swaps.md` is a diff, so an edit that reflows the file destroys the record it
is supposed to produce. Measured, not assumed — a `Deck.dump()` round trip
changes 829 lines of Goreclaw and deletes all 8 of its comments; a ruamel
round trip changes 6–132 depending on the file. A surgical swap changes 2–5.

## Consequences

- Fixing a banned card is now three clicks and a sentence, and the gate result
  updates in the same view. Goreclaw goes from one error to valid without
  leaving the page.
- **The API is no longer read-only**, and that is a real change in posture. It
  is one endpoint, it validates everything before writing, it writes whole
  files rather than in place, and it refuses more often than it accepts. When
  auth arrives, it is also the first endpoint that must be user-scoped.
- The write goes through `DeckSource`, so the same code path serves a file
  today and a database row later — `docs/HOSTING.md` stores a user deck as the
  same YAML text, which is what makes a *text* edit portable between them.
- Committing is still the user's job. The tool changes the working tree and
  says so; it does not commit, and it does not decide when a deck's history
  should record something.
- A deck can now be edited by something other than a text editor, which means
  the YAML formatting conventions in those files are load-bearing. The editor
  preserves them; the tests in `tests/test_edit.py` are what keep that true.
