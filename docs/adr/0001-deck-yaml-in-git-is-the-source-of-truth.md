# 1. `deck.yaml` in git is the source of truth

**Status:** Accepted · **Decided:** during the deck migration · **Recorded:** 2026-08-10

## Context

The six curated decks began as hand-maintained markdown in `~/Downloads` — a
decklist, a primer, and a pile of prose about how the deck works. That format
has one failure mode and it is severe: **prose drifts from fact, and nothing
notices.** The migration found, in documents that read as authoritative:

- a curve counted by hand as 8/15/17/14/6/3, average 3.06, where the corpus
  says 9/13/20/13/4/4, average 3.03;
- a claim that the commander is castable by turn five in 67% of games, where
  20,000 simulated games say 57.2%;
- `Captain America's Aid`, which is not a card — the source's own
  parenthetical named the real one, Sigarda's Aid;
- Arahbo's {1}{G}{W} doubling described as an eminence ability, which it is
  not.

Every one of those was checkable. None was checked, because there was nothing
to check them with.

## Options considered

**Keep markdown as the source and parse it.** Rejected. The parsing problem is
open-ended — the interesting content is prose — and it leaves the drift problem
exactly where it was. The document would still be the thing a human edits.

**Put decks in a database.** Rejected for the curated decks. It gives up
diffability and history, requires a running service to inspect a deck, and
turns "what changed between these two versions" into a feature someone has to
build.

**Structured files in git, with documents generated from them.** Chosen.

## Decision

`decks/<slug>/deck.yaml` is the only source of truth. Everything under
`decks/<slug>/artifacts/` is generated by `mtglab decks build` and is never
hand-edited. The original markdown is historical: it must not be edited or
re-imported, because it contains the wrong claims listed above.

**Deck history is git history.** There is no version table and no migration.
`git log -p decks/gyome-food/deck.yaml` is the swap record, and `swaps.md` is
literally a git diff against a previous revision of the file.

Every card carries a `why`. Validation fails without one, on the theory that a
card which cannot justify its slot is a card to cut.

## Consequences

- Every claim about a deck is regenerable, so a wrong number is a bug in code
  rather than a typo in prose. The Phyrexian mana-value bug found on 2026-08-10
  is the pattern working: it moved two Tivit cards into the wrong curve bucket,
  and it was found by a test rather than by a reader.
- The gate (`mtglab decks validate`) can run in CI, because a deck is data.
- Swap history costs nothing to maintain and cannot get out of sync with the
  deck, because it *is* the deck's history.
- **Editing a deck needs an editor and a commit, not a UI.** Correct for the
  maintainer, and the reason a hosted instance needs a second, database-backed
  tier for other people's decks — see [ADR 4](0004-two-embedded-databases.md).
- **`swaps.md` only appears if you committed before editing.** A real footgun,
  documented in the CLAUDE.md workflow. The alternative — the tool keeping its
  own shadow copy — would reintroduce the drift this decision exists to remove.
